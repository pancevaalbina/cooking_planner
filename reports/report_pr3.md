## Доработка индивидуального проекта
**Название:** Планировщик приготовления нескольких блюд

**Классы, добавленные/переработанные на ПР3:**
- `Task` (и наследники `ActiveTask`, `PassiveTask`) — задача рецепта;
  демонстрирует наследование и полиморфизм (`requires_cook`,
  переопределенный `describe()`), `@staticmethod validate_minutes()`,
  `@classmethod from_dict()`.
- `Recipe` — рецепт как композиция задач (`total_minutes`,
  `active_minutes`).
- `Dish` — блюдо (`id`, `name`, `servings`, `recipe`); `__str__()`,
  `@staticmethod validate_servings()`, `to_dict()/from_dict()`.
- `PlanEntry` — запись плана, связывающая `Dish` со временем подачи;
  `cancel()` меняет состояние, не удаляя запись; `__str__()` учитывает
  состояние; хранит ссылку на объект `Dish` (композиция), а не только
  его id.

**Описание доработки:** функциональная модель ПР2 (словари и списки)
переработана в объектную. Проверка «блюдо не помещается по времени»
(`check_room_capacity` в примере методички) стала свойством
`Dish.total_time`; функция `is_room_available` — `is_time_free()`,
проверяющей пересечение активных задач разных блюд; `remove_from_plan`
заменена на `cancel_plan_entry()`, не удаляющий запись из коллекции, а
меняющий её состояние (как в примере с `Booking.cancel()`). Функция
`get_start_status()` из ПР1 перенесена без изменений. Функции общего
назначения (`input_int`, `input_datetime`) и загрузка/сохранение JSON
остались обычными функциями.

## Результат работы
- основные сущности (`Dish`, `Task`/`Recipe`, `PlanEntry`) представлены
  классами; созданы их объекты;
- реализованы атрибуты и методы, `__init__()` и `__str__()`;
- организовано взаимодействие объектов (`PlanEntry.dish -> Dish.recipe
  -> [Task]`);
- функциональность ПР2 сохранена и адаптирована к объектной модели;
- данные по-прежнему хранятся в JSON, загрузка создает объекты, при
  сохранении объекты преобразуются обратно в JSON;
- сохранена обработка исключений (`ValueError` при некорректных
  данных, `FileNotFoundError`/`JSONDecodeError` при чтении файлов);
- тесты адаптированы (18 тестов pytest проходят), код проверен flake8
  без замечаний, README.md обновлен.

## Вывод
Проект переведен с функциональной модели (словари, списки, функции
ПР2) на объектно-ориентированную: сущности предметной области —
блюдо, рецепт, задача и запись плана — теперь объекты соответствующих
классов с собственными атрибутами и поведением. Рассмотрены наследование
(ActiveTask/PassiveTask), полиморфизм (переопределенный describe()),
инкапсуляция (защищенный список задач в Recipe, доступ через свойство)
и декораторы (`@staticmethod`, `@classmethod`, `@log_call` с
`functools.wraps`). Существующая функциональность и тесты сохранены.
